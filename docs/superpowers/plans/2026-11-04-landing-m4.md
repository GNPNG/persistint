# The Landing, mechanics M4: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give The Landing what its spec asks for and the build lacks: commands from two voices, escalation, a definite end where the ship lands, and crew tasks that save failed systems (bead persistint-game-usl0.1).

**Architecture:** `landing.gd` keeps one control flow. The single `current` command becomes an array of command *slots*, each with a speaker and its own timer. A resolved-command counter drives the escalation (shorter timers, a second slot) and the end (the landing). Crew tasks gain one effect: doing a task at a station whose system has failed restores that station. All tuning values live in `landing.json`.

**Tech Stack:** Godot 4.6.3, GDScript; headless SceneTree tests.

**Spec:** M4 in `docs/design/minigames-gap-report.md` on branch `origin/srv/minigames-gap-report`: "a second voice (the first mate) issuing commands over the player's station, escalation (shorter timers, two commands at once), a definite end (the landing), the crew tasks wired to something (a task done = a system saved)". Also The Landing in `docs/DESIGN.md` §2.

## Global Constraints

- No new player-facing prose (the gap report's D1: framing text is the author's). Every line the player sees comes from existing data (command text, speaker names) or from empty author slots in `landing.json`. Do not add, edit or remove any command or crew-task text.
- Godot 4.6.3 (`godot` on PATH). Typed GDScript in the existing style: tabs, `##` doc comments.
- Tests are headless SceneTree scripts in `project/tests/`, run with `godot --headless --path project -s tests/<file>.gd` from the worktree root. A test passes on `RESULT: PASS` and exit code 0. `project/tests/test_landing_crew.gd` must pass unchanged. Before the last commit, run the whole suite: `tools/run_tests.sh`.
- Keep the existing WorldState flags (`landing_done`, `landing_score`, `landing_failed`, `landing_tasks_done`). Add `landing_outcome` (String) and `landing_saved` (Array of station names).
- New `landing.json` values, used exactly: `"seconds_min": 4.0`, `"commands_to_land": 24`, `"two_at_once_after": 8`, `"rough_max_failed": 3`, `"end_card": {"smooth": "", "rough": "", "hard": ""}`. `"seconds_per_command": 8.0` stays.
- No Python. No new art or audio files.
- Commits are authored and committed by Brett Whitty <brett@gnomatix.com>, with no AI-attribution trailers. Work on branch `wsl2/usl0-m4-landing`. Don't push.

## Rulings (decisions this plan makes where the spec is silent)

- R1 Second voice: commands come from two speakers. Slot 0 is the First Mate (`data.first_mate`, as now); slot 1 is the Captain (`captain_name()`). Each shout line reads `"<speaker>: <command text>"`, as the current one does. Slot 1 opens only with escalation. No character art.
- R2 Escalation: a command's time falls linearly from `seconds_per_command` (8.0) to `seconds_min` (4.0) over `commands_to_land` resolved commands, and never goes below 4.0. Slot 1 opens once `two_at_once_after` (8) commands have been resolved.
- R3 End: the ship lands when `commands_to_land` (24) commands have been resolved, whether pressed or timed out. A descent bar shows the progress. The queue reshuffles all commands when it runs dry, so the run never ends early.
- R4 Outcome: `"smooth"` with 0 failed stations, `"rough"` with 1 to `rough_max_failed` (3), `"hard"` with more. The end shows `end_card[outcome]` only when it isn't empty (they're the author's slots).
- R5 A task saves a system: doing a not-yet-done task at a station in `failed` removes that station from `failed`, re-enables its controls and appends it to `saved`.
- R6 One press resolves at most one slot, checking slot 0 first. `fill_slots()` never puts the same control in both active slots.

## Review Focus

1. Both active slots name the same station, and the player presses one slot's control. Exactly one command resolves, and the other keeps running (test in Task 1).
2. The run ends exactly once. After the landing, `_process`, `press` and further timeouts change nothing, and only one OK button exists (test in Task 2).
3. The queue runs dry before 24 resolutions. The run carries on with reshuffled commands instead of finishing (test in Task 1).
4. A slot's station fails while the player is standing there. Its controls disable at once, and the other slot still resolves normally (test in Task 1).
5. A station is saved while its command is active in a slot. The command can be pressed again once the station is restored (test in Task 3).

### Task 1: Two command slots and escalation

**Files:**
- Modify: `project/data/landing.json`: add the five new keys from Global Constraints next to `seconds_per_command`.
- Modify: `project/scripts/minigames/landing.gd`: replace `current`/`time_left` with slots; replace the single shout line and timer with one per slot (slot 1's hidden until open).
- Create: `project/tests/test_landing_m4.gd`, in the same shape as `test_landing_crew.gd` (`_check`, `RESULT:` line, `quit(_failures)`).

**Interfaces:**
- Produces, in `landing.gd`:
  - `var slots: Array[Dictionary]`: each entry is `{"who": String, "cmd": Dictionary, "time_left": float, "max": float}`.
  - `var resolved := 0`
  - `func seconds_for(n: int) -> float`
  - `func active_slot_count(n: int) -> int`
  - `func fill_slots() -> void`: opens and refills slots up to `active_slot_count(resolved)`, drawing from `queue` and refilling `queue` from a shuffled copy of `data.commands` when it's empty (R3, R6).
  - `func press(control: String) -> void`: resolves the first matching slot at the current station (R6).
  - `func _resolve(i: int) -> void`: `resolved += 1`, then `_finish()` once `resolved >= commands_to_land`, else `fill_slots()`. Task 2 builds the finish.
  - `func _slot_times_out(i: int) -> void`: the slot's station joins `failed` (once), then `_resolve(i)`.
- `_process(delta)` counts down every active slot and calls `_slot_times_out` for each one that reaches 0.
- `_ready()` calls `fill_slots()` where it now calls `_next_command()`. `_next_command()` goes away.
